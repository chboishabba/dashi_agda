# Governance and standards alignment

[Back to the contract overview](README.md)

This is a lightweight engineering control surface for the proof repository. It is not a certification statement and does not claim full conformity with any external standard.

## Change and service management

ITIL-style change control is applied through a dedicated branch, a stacked draft pull request, a written purpose, explicit authority boundaries, cumulative validation and a rollback point at the Round 22 base.

Incidents are concrete proof or integration failures: type errors, a counterexample to a claimed inequality, missing source fidelity, cutoff dependence, circularity or a failed workflow. Each incident must produce either a repair or a narrowed theorem statement.

## Quality management

ISO 9001 and Six Sigma principles are represented by:

- one canonical requirement surface;
- traceability from official clause to Agda field, proof producer and test;
- defect prevention through fail-closed status constructors;
- measured queue quality rather than commit count;
- root-cause analysis for every falsified estimate;
- no promotion without repeatable verification evidence.

## AI and model risk

ISO/IEC 42001, ISO/IEC 23894 and the NIST AI RMF are represented by:

- clear separation between generated proposals and checked mathematics;
- source provenance and preprint status in theorem headers;
- explicit uncertainty and authority boundaries;
- independent counterexample testing;
- human-review checkpoints before promotion;
- no claim that an LLM, bot review or static grep establishes mathematical truth;
- a fail-closed final status until the kernel check and physical producers are complete.

## Information security and privacy

ISO/IEC 27001 and ISO/IEC 27701 are represented by:

- no secrets, tokens or personal data in proof artifacts;
- least-privilege repository operations;
- immutable commit history for evidence;
- no external telemetry requirement in the checker;
- deterministic source and validation paths where practical;
- security or privacy findings treated as release-blocking defects.

## Human factors, accessibility and interaction quality

ISO 9241-110, ISO 9241-161, ISO 9241-210, ISO 9241-306, ISO 24552, ISO 16817, ISO 24505 and ISO 22727 are represented at the documentation surface by:

- plain-language headings and short sentences;
- explicit status words: exact target, checked reducer and open producer;
- no meaning conveyed by color alone;
- relative links and a single navigation parent;
- readable tables with textual equivalents;
- PlantUML source that can be rendered in accessible alternatives;
- predictable names for requirements, tests and authority boundaries;
- no hidden interaction or required graphical interface to inspect the proof state.

The identifiers above are retained in the control registry because they were requested for the project. Detailed clause-by-clause conformity assessment is outside this mathematical implementation round.

## Release and promotion rule

The branch may leave draft status only after:

1. the cumulative Agda root passes;
2. every new authority boundary is reviewed;
3. documentation links and PlantUML parse checks pass;
4. no unsafe or placeholder marker is present;
5. the pull request accurately states which physical producers remain open.

The Clay theorem flag may change only after the exact physical carrier inhabits the literal Fefferman statement. Repository structure, documentation completeness, bot approval or the number of formal reducers are not sufficient.
