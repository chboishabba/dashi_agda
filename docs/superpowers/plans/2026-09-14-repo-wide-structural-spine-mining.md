# Repo-Wide Structural Spine Mining

**Goal:** Apply the same extraction modality used for coarse/fine and candidate-family execution to arbitrary DASHI lanes: mine repeated structural moves, reuse an existing canonical owner when one exists, add an exact crosswalk when multiple equivalent carriers already exist, and create a new Core carrier only after multiple independent manifestations justify it.

## Method

For every apparently random lane-local construction:

```text
manifestation
-> identify consumer
-> identify exact carrier / obligation
-> search existing Core / Interop owners
-> classify relationship
   SAME CARRIER       -> direct reuse / alias / thin adapter
   EQUIVALENT CARRIER -> prove bidirectional crosswalk
   STRICT REFINEMENT  -> preserve richer carrier, expose projection to parent
   ANALOGY ONLY        -> no theorem transport
   MISSING STRUCTURE   -> explicit unpaid seam
-> return generic theorems back to domain consumers
-> retain provenance / status / source roles
-> register validated canonical owners
-> only then consider deprecating duplicate local machinery
```

Canonical promotion requires typed factorisation or exact translation, not lexical similarity.

The programme is deliberately bidirectional: domains contribute witnesses into a generic spine, and the generic spine must return useful theorems to those domains. A one-way renaming exercise is not consolidation.

## WrongType / negative knowledge note

Repo-wide mining shows two meanings that must remain distinct:

1. SensibLaw/legal `WrongType` objects with domain-specific legal semantics;
2. general fail-closed promotion firewalls implemented as empty types or mismatch receipts.

Do not merge these by vocabulary alone.

The abstract `WrongTypeAttributionFactorisationPlanningSnowballExact` already maps its factorisation-error receipt into the canonical non-factorability machinery. This is healthy reuse; it needs at most a thin crosswalk into the projection-collision surface, not a new universal `DoesNotEntail` ontology.

An empty promotion type documents that no constructor is supplied; by itself it should not be over-read as a semantic non-entailment theorem unless the owning module provides the relevant interpretation.

## Mining priority function

Rank a proposed extraction roughly by:

```text
(number of real consumers unlocked)
* (independent domains)
* (duplicate machinery removed)
* (open payments clarified)
* (future theorem reuse)
/
(new abstraction complexity + migration risk)
```

Prefer exact crosswalks over new carriers when equivalent machinery already exists.

## Non-collapse rule

The programme is not "everything is secretly the same thing." It is:

```text
same theorem shape -> crosswalk/reuse
strictly richer theorem -> parent projection + retained extra structure
shared analogy only -> provenance note, no transport
incompatible obligations -> keep separate
```
