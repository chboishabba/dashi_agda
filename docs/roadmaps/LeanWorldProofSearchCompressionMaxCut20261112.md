## Decision: one evolving world, not 21,481 repository pairs

No global pairwise theorem enumeration, no permanent arbitrary proof execution traces and no duplicate world builder. Ingestion is source-first and immutable. **Elaborated typed theorem DAG** is the logical representation; exact source and proof occurrences are never erased by physical structural sharing. Indexed fibres, versioned transport and PNF residuals permit bounded candidate *discovery*, not unproved identification. Search targets are a goal or an incremental changed dependency cone; non-promoted matches remain candidates.

```text
Pinned original source bytes / licences / original authors and timestamps
  -> Lean elaborated Expr / original theorem occurrences [UNPAID real corpus admission]
  -> binder-safe hash-consed logical DAG + version-delta source graph
       +-> exact type equality bucket, typed structural/Agda preflight fibre
       |     -> Aristotle AND/OR proof hypergraph + PNF residual frontier
       |     -> bounded candidate subset -> typed Lean proof composition
       |     -> immutable oriented checked proof transport edge
       +-> MDL candidate grammar + bounded program synthesis where supported
             -> exact original AST/proof reconstruction + full cost comparison
             -> compact physical encoding, no redundant stored traces
  -> PostgreSQL versioned world + existing CID/ZOS/Kant federation interfaces
```

The **logical DAG is not necessarily the smallest physical serialization**: the same typed objects must be benchmarked as compressed trees, shared DAGs, parameterised grammars, proven generative codecs and hybrid layouts. A program is admitted for lossless storage only with exact reconstruction and strictly lower *total* measured cost. FRACTRAN is a specialised backend, not a default representation for every theorem.

## What changes when expressions look similar

| Examples | Exact canonical type identity? | Shared physical nodes? | Typed fibre / residual |
|---|---|---|---|
| `(x : Nat) → x + 0 = x` vs `(n : Nat) → n + 0 = n` | **Yes**, with identical elaborated binders, constants and universe context | Yes | No residual from a binder-name difference |
| `x + 0 = x` vs `x + 1 = x` | **No** | Common binder, `Nat`, application and equality nodes can be shared | Same coarse shape may yield a candidate; literal/goal mismatch must survive |
| `a + b = b + a` vs `n + m = m + n` with binder order permuted | **Not automatically** | Significant substructure may share | Permutation/commutativity transport must be checked unless terms become literally alpha-equivalent under the chosen binder correspondence |
| Same printed `add`, different fully qualified constants/instances | **No** | Only typed lower-level shared nodes if genuinely identical | Projection collision is not equivalence |
| Same proof outcome/isospectral trace, different order or history | **No automatic identity** | May share patterns | Temporal, trace and scope residuals retained |
