## Important further original-readback: security remediation was already partly CLOSED at report date

**Do not conflate a 35m-person database vulnerability with a copy of 35m people's records in the researcher-downloaded GitLab tree.** Joint report paragraphs **95–107** provide a more precise chain: a 20 March 2018 GitLab discovery; repository files included access credentials/keys to separate client databases covering ~35m persons; the researcher **said they did not download those databases**. The report separately describes residual personal information in repository backups. Report ¶101 describes a disclosed script on an SCL employee's GitHub account pointing at the AIQ GitLab instance; this is an actual *discovery-route object*, not proof of shared covert control.

Critically, ¶¶**104,107** say AIQ implemented protective arrangements and **supplied the regulator offices with a sworn affidavit attesting to deletion of specified personal information**, and the commissioners regarded the **security-safeguards issue as resolved** at publication. This supports a scoped **remediation submission + regulator acceptance**, distinct from the report's overall **conditional** investigation status and planned six-month implementation follow-up.
