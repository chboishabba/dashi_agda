# Application transformation, possession and succession pass — 2026-09-06

The discriminating technical object is often not the governing physics itself but the transformation from generally known science to a calibrated, configured, qualified and reproducible application:

`known law/model + configuration + calibration + closure/regularisation + operating window + failure history + qualification + workflow -> usable capability`.

Two teams may know the same equations while possessing materially different capabilities. Public architecture therefore cannot be used as a proxy for public operational capability.

## Distribution firewall

`distributed programme surface != distributed critical carrier`.

A multi-lab programme, multi-author publication, shared database, or written procedure cannot by itself establish that the exact calibration/process/failure/inverse-model carrier was distributed.

Conversely, `visible senior role != concentrated carrier`.

Concentration and succession must be proved for the same technical object.
